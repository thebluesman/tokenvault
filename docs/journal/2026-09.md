# Project Journal — 2026-09

## 2026-09-01

- **[decision]** Duration/easing tokens have no native Figma Variables/Styles type. When importing, surface an explicit flag/tag step for user-marked number Variables; defer manual entry to Phase 4 when no Variable exists. _Avoids guessing token semantics._ Updated GitHub issue #2 acceptance criteria; renamed `area:figma-apply` → `area:figma-io` label. → [docs/prd.md §6.1, §6.5.1](../prd.md)
- **[decision]** Follow-up: opacity is auto-detectable via `VariableScope.OPACITY` in Figma's Plugin API when present, but duration/easing has no corresponding scope value. _Asymmetry means different auto-detect pathways for the two ambiguous number types._ Updated docs/prd.md §6.1 and §6.5.1 with the distinction; revised GitHub issue #2 acceptance criteria to describe VariableScope-based auto-detect for opacity. → [docs/prd.md §6.1–6.5.1](../prd.md)
- **[decision]** Phase 3 architecture: Figma Styles → token JSON in four synthetic sets (`tokens/styles/{paint,text,effect,grid}.json`), mapping paint/text/effect/grid styles to DTCG color/typography/shadow/grid types with provable-mirror de-noising and Variables-win cross-source collision precedence. _Styles carry composite types and no modes; extension on ADR-0002's design, with new collision rules and fail-loud report kinds._ → [docs/adr/0003-styles-token-schema.md](../adr/0003-styles-token-schema.md)
- **[design]** First UX documentation published: Phase 4 (Local editor) token-browsing and inline-editing UI. Establishes set-switcher navigation, nested disclosure tree from DTCG paths, inline editors for scalars (color/number/boolean/string), full-panel overlays for composites (typography/shadow/grid), and create/delete/search flows with live validation. _Phases 2–3 produced real imported data; now ready to firm up design before frontend build begins._ Surfaces 5 open design questions (§10): persistence model, single-set vs. merged view, delete protection, hand-created tokens, and token rename. → [docs/ux/README.md](../ux/README.md) and [docs/ux/local-editor.md](../ux/local-editor.md)
- **[decision]** Phase 4 persistence model finalized: edits stored as clientStorage overlay (target+op+value+base), not tree snapshot; rescan performs three-way merge instead of destructive overwrite. Token creation and rename deferred — neither has downstream consumers yet; rename also requires reference-rewriting beyond Phase 4. _Architecture preserves user edits across rescans; deferred features become Phase 5/6/7 decisions once consumers exist._ → [ADR-0004](../adr/0004-local-edit-persistence.md), [issue #7](https://github.com/thebluesman/tokenvault/issues/7)
- **[design]** docs/ux/local-editor.md updated to reflect ADR-0004 persistence: "rescan will discard your edits" blocking dialog removed; replaced with post-scan merge-summary UI; header chip reads "Local edits · N" (not "unsaved changes"); new §5.5 defines edit-conflict and orphaned-edit review flows. _Edit preservation changes UX from a warning barrier to a merge outcome._ → [docs/ux/local-editor.md](../ux/local-editor.md)
- **[design]** Phase 4 token browser redesigned from single-set to merged multi-set view, keyed by dotted path instead of by token. The 289 paths `Theme/Light` and `Theme/Dark` share now appear once with a stacked value line per set (§4.2), rather than twice. _Enables side-by-side theme comparison in one screen; set navigation becomes a multi-select filter (§4.3) instead of a mode switch._ Reverses the doc's original single-set recommendation (§10.2). → [docs/ux/local-editor.md §4](../ux/local-editor.md)
- **[design]** Phase 4 delete protection finalized: tokens with inbound references are now undeletable outright, not warned-and-allowed. The delete control is disabled with an explanation panel that names each referrer by path and set (§7). _Phase 4 cannot edit references, so blocking prevents user-created dangling references; reference surgery and token rename both defer to Phase 7._ → [docs/ux/local-editor.md §7](../ux/local-editor.md)

## 2026-09-02

- **[decision]** Phase 5 apply and drift: architecture proposed. Overlay-based apply writes only edited tokens (preview + post-apply rescan); drift detection extends Phase 4's three-way merge to all tokens, baselining from import cache. _Reuses existing merge logic; no new infra; keeps apply surface small._ Two open decisions for Shyam: strict conflict handling (refuse conflicted targets), and whether plugin should delete Figma variables. → [docs/adr/0005-figma-apply-and-drift.md](../adr/0005-figma-apply-and-drift.md)
- **[decision]** Shyam resolved four open Phase 5 questions (2026-09-02): (1) apply always shows confirmation, no "don't ask again" shortcut; (2) conflicted targets block apply until user picks a side; (3) Figma variable/style deletion is allowed but behind its own separate, destructive confirmation, never bundled into an apply; (4) applying a token-to-token reference preserves it as a native Figma variable alias instead of flattening it to the resolved value — pulling alias *writing* forward from Phase 7 to Phase 5. _Scope change on aliasing (writing only, not editing yet); strict confirmation and conflict handling clarify safe defaults._ ADR-0005 and docs/ux/apply-and-drift.md updated; status remains Proposed. → [docs/adr/0005-figma-apply-and-drift.md §5, §6, §10, §11](../adr/0005-figma-apply-and-drift.md), [docs/ux/apply-and-drift.md §5.2, §5.6, §5.7](../ux/apply-and-drift.md)
- **[design]** Phase 5 apply and drift design fully closed: ADR-0005 confirms library-variable refusal and defers UI questions to UX doc; UX doc finalizes apply modal, drift ⚑ badge, native ⌘Z undo, and green *in sync* state. _All Phase 5 design questions resolved; implementation-ready._ → [docs/adr/0005-figma-apply-and-drift.md](../adr/0005-figma-apply-and-drift.md), [docs/ux/apply-and-drift.md](../ux/apply-and-drift.md)
